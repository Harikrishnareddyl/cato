# Cato v0.4.0 — Sandbox Runtime Spec

## Vision

Cato becomes an OS-level sandbox. You `cato run` in your project directory and everything inside is kernel-enforced. Any process, any agent, any user. No hooks, no cooperation needed. Inside the sandbox, the host doesn't exist — only the workspace, allowed tools, and injected secrets.

## Scope

- **Platform:** macOS only (`sandbox-exec` / Seatbelt)
- **Linux:** Future (bubblewrap/Landlock)
- **Reference:** Anthropic's `@anthropic-ai/sandbox-runtime` (learn from, build independent)

## Core flow

```bash
cd my-project
cato init                              # creates .cato.toml
cato tool add node git claude          # register tools (one time)
cato secret put ANTHROPIC_API_KEY      # store secrets (one time)
cato run                               # enter sandbox
```

## CLI commands

| Command | What it does |
|---------|-------------|
| `cato init` | Create `.cato.toml` in current directory |
| `cato tool add <name>` | Find and register a tool binary |
| `cato tool add <name> --path /x` | Register with explicit path |
| `cato tool list` | List registered tools |
| `cato tool remove <name>` | Remove a tool |
| `cato secret put <NAME>` | Store a secret (prompts for value) |
| `cato secret put <NAME>=<val>` | Store a secret with value |
| `cato secret list` | List stored secrets (names only) |
| `cato secret remove <NAME>` | Remove a secret |
| `cato run` | Enter sandbox (current dir = workspace) |
| `cato run -- <command>` | Run single command in sandbox |
| `cato run --ephemeral` | Sandbox with disposable copy |
| `cato status` | Show sandbox readiness |

## Global store (`~/.cato/`)

Tools and secrets are registered once per machine. Stored on the host, never visible inside the sandbox.

```toml
# ~/.cato/store.toml (auto-managed, never committed)

[tools]
node = "/opt/homebrew/bin/node"
python3 = "/opt/homebrew/bin/python3"
git = "/usr/bin/git"
claude = "/opt/homebrew/bin/claude"
npm = "/opt/homebrew/bin/npm"

[secrets]
ANTHROPIC_API_KEY = "sk-ant-..."
DATABASE_URL = "postgres://localhost/mydb"

# Project-scoped secret overrides (override global for specific projects)
[secrets.projects."/Users/hari/projects/my-app"]
DATABASE_URL = "postgres://localhost/myapp_dev"

[secrets.projects."/Users/hari/projects/other-app"]
DATABASE_URL = "postgres://localhost/otherapp_dev"
STRIPE_KEY = "sk_test_..."
```

### Secret resolution order

When `cato run` resolves a secret declared in `.cato.toml`:

```
1. Host environment variable (e.g., export ANTHROPIC_API_KEY=...)
2. Project-scoped store (secrets.projects."/path/to/cwd" in store.toml)
3. Global store (secrets.* in store.toml)
4. Default value (from .cato.toml: { default = "value" })
5. Warning (secret not found, not injected)
```

This allows the same machine to have different database URLs per project, while
sharing a single API key globally. Host env vars always win (useful for CI).

### `cato tool add`

```bash
$ cato tool add node
[cato] ✓ node → /opt/homebrew/bin/node

$ cato tool add python3 --path /usr/local/bin/python3
[cato] ✓ python3 → /usr/local/bin/python3

$ cato tool add kubectl
[cato] ✗ kubectl not found in PATH
[cato]   Install it or: cato tool add kubectl --path /path/to/kubectl
```

Finds the binary via `which`, saves the absolute path. The sandbox allows reading/executing only these specific paths — no broad `/opt/homebrew/` access.

### `cato secret put`

```bash
# Global secret (available to all projects)
$ cato secret put ANTHROPIC_API_KEY
Enter value: sk-ant-...
[cato] ✓ ANTHROPIC_API_KEY saved (global)

$ cato secret put DATABASE_URL=postgres://localhost/mydb
[cato] ✓ DATABASE_URL saved (global)

# Project-scoped override (only for current directory's project)
$ cato secret put DATABASE_URL=postgres://localhost/myapp_dev --project
[cato] ✓ DATABASE_URL saved (project: /Users/hari/projects/my-app)

$ cato secret put STRIPE_KEY --project
Enter value: sk_test_...
[cato] ✓ STRIPE_KEY saved (project: /Users/hari/projects/my-app)
```

Global secrets are the default. Use `--project` to scope a secret to the current
working directory's project. Project secrets override global secrets of the same name.

```bash
# List shows both scopes
$ cato secret list
Global:
  ANTHROPIC_API_KEY = sk-a****
  DATABASE_URL = post****

Project (/Users/hari/projects/my-app):
  DATABASE_URL = post****  (overrides global)
  STRIPE_KEY = sk_t****

# Remove project-scoped override
$ cato secret remove DATABASE_URL --project
[cato] ✓ DATABASE_URL removed (project scope)
```

Secrets are stored in `~/.cato/store.toml` on the host. When `cato run` starts, matching secrets are injected as environment variables into the sandbox. The store file itself is never accessible inside.

## Project config (`.cato.toml`)

Committed to git. Declares what the project needs.

```toml
# .cato.toml

[sandbox]
# Filesystem — workspace is writable, rest blocked
writable = ["{workspace}", "/tmp"]

# Filesystem — explicitly blocked from reading (even within readable paths)
deny_read = [
    "*.env",
    "*.env.*",
    "*.pem",
    "*.key",
    "id_rsa",
    "id_ed25519",
    "*credentials*",
]

# Network — only these domains reachable
network = [
    "github.com",
    "api.anthropic.com",
    "registry.npmjs.org",
]

# Tools needed inside
tools = ["node", "git", "claude", "npm"]

# Secrets needed inside (values come from host env or ~/.cato/store.toml)
[sandbox.secrets]
ANTHROPIC_API_KEY = {}
DATABASE_URL = { default = "postgres://localhost/mydb" }
NODE_ENV = { default = "development" }

# Options
[sandbox.options]
ssh_agent = true
allow_localhost = true
```

## How `cato run` works

```
1. Read .cato.toml from current directory
   → Not found? Error: "Run cato init"
   → Check CATO_SANDBOX env → already in sandbox? Error: "Exit first"

2. Check requirements:
   For each tool in .cato.toml:
     → Look in ~/.cato/store.toml → found? use that path
     → Try `which <tool>` → found? use it
     → Not found? Error: "Run cato tool add <tool>"

   For each secret in .cato.toml:
     → Check host environment variable → found? use it
     → Check project-scoped store → found? use it
     → Check global store → found? use it
     → Has default in config? → use default
     → Not found? Warning (non-fatal)

3. All requirements met → build sandbox:
   → Generate Seatbelt profile from config (deny-default model)
   → Prepare env vars (secrets + system vars + CATO_SANDBOX=1)
   → Create temp ZDOTDIR with custom .zshrc for 🔒 prompt
   → If --ephemeral: copy workspace to /tmp/cato-eph-XXXXX/
   → Log sandbox_start to ~/.cato/audit.jsonl

4. Enter sandbox:
   → /usr/bin/sandbox-exec -f /tmp/cato-XXXXX.sb /bin/zsh
   → Or: sandbox-exec -f profile /bin/sh -c <command> (single command mode)
   → Environment: cleared + HOME, USER, SHELL, TERM, LANG, PATH, CATO_SANDBOX,
     ZDOTDIR, SSH_AUTH_SOCK (if enabled), injected secrets

5. Cleanup:
   → Remove temp profile file
   → If --ephemeral: remove workspace copy
   → Log sandbox_stop to ~/.cato/audit.jsonl
```

## Isolation model

**Inside the sandbox, the host doesn't exist.** Only these are visible:

| What | Access | Source |
|------|--------|--------|
| Workspace directory | read-write | mounted from host |
| `/tmp` | read-write | host /tmp |
| System binaries (`/usr`, `/bin`, `/sbin`) | read-only | host (needed for shell/OS) |
| Registered tool binaries (specific paths) | read-only | from `~/.cato/store.toml` |
| Secrets | env vars only | from host env or `~/.cato/store.toml` |
| SSH agent socket | socket only | forwarded if `ssh_agent = true` |
| Network | allowed domains only | resolved at sandbox creation |
| `.cato.toml` | read-only | readable for git ops, writes blocked |
| `~/.cato/` | **not visible** | — |
| `~/` (home dir) | **not visible** | — |
| `.env`, `*.pem`, etc. | **not visible** | blocked by `deny_read` |

### Why this model works for auth

Tools authenticate themselves inside the sandbox using the injected env vars:

```bash
🔒 $ claude        # reads ANTHROPIC_API_KEY from env → authenticates
🔒 $ git push      # uses SSH_AUTH_SOCK → authenticates via agent
🔒 $ npm install   # no auth needed (public registry)
```

No host config files needed. No `~/.claude/`, no `~/.ssh/id_rsa`. The tools get what they need as env vars or sockets — nothing more.

### CI/cloud — no setup needed

```yaml
# GitHub Actions
env:
  ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
run: |
  cato init --minimal
  cato run -- claude "review this PR"
```

Secrets come from CI env vars. `cato run` detects them automatically — no `cato secret put` needed. Tools are found via `which` — no `cato tool add` needed.

## Architecture

```
Host (unsandboxed)
  │
  ├── ~/.cato/
  │   ├── store.toml          ← tool paths + secrets (never in sandbox)
  │   └── audit.jsonl         ← sandbox event log
  │
  ├── cato binary (runs on host)
  │     │
  │     ├── Read .cato.toml
  │     ├── Read ~/.cato/store.toml
  │     ├── Check requirements
  │     ├── Resolve DNS for network domains
  │     ├── Generate Seatbelt profile
  │     ├── Prepare env vars
  │     ├── Log sandbox_start
  │     └── exec: sandbox-exec -f profile.sb -- /bin/zsh
  │
  └── Sandbox (kernel-enforced)
        ├── workspace: read-write
        ├── /tmp: read-write
        ├── tool binaries: read-only (specific paths)
        ├── system binaries: read-only (/usr, /bin, etc.)
        ├── env vars: secrets + CATO_SANDBOX=1
        ├── SSH_AUTH_SOCK: forwarded
        ├── network: allowed IPs only
        ├── everything else: DOES NOT EXIST
        └── all child processes inherit restrictions
```

## Implementation steps

### Step 1: Minimal sandbox — filesystem write restrictions ✅

**Goal:** `cato run` drops into a shell where writes outside workspace are blocked.

**Build:**
- `src/sandbox/` module
- Parse `[sandbox]` from `.cato.toml` (just `writable`)
- Generate Seatbelt profile
- Execute `sandbox-exec -f profile /bin/zsh`
- Set `CATO_SANDBOX=1`, detect nested sandbox

**Implementation decisions (differs from original spec):**

The original spec proposed `(allow default)` + selective denies. This was replaced with
a **deny-default model**: `(deny default)` + explicit allows. Reasons:

1. `(allow default)` + deny-read didn't work — the broad allow overrides specific denies
2. Deny-default is more secure — anything not explicitly allowed is blocked
3. Home directory is invisible by default (not just "permission denied" — it doesn't exist)

**Seatbelt profile architecture (deny-default):**
```scheme
(version 1)
(deny default)

; Essential system operations
(allow file-read-metadata)            ; stat/lstat for path traversal
(allow file-read* (literal "/"))      ; root dir — macOS symlinks need this
(allow process-exec*)                 ; execute binaries
(allow process-fork)                  ; spawn processes
(allow mach-lookup)                   ; all mach IPC (varies by macOS version)
(allow sysctl-read)                   ; all sysctl reads (varies by macOS version)
(allow ipc-posix-shm)                ; shared memory
(allow pseudo-tty)                    ; terminal support

; System reads (read-only)
(allow file-read* (subpath "/usr"))
(allow file-read* (subpath "/bin"))
(allow file-read* (subpath "/System"))
; ... etc

; Workspace (read-write)
(allow file-read* (subpath "<workspace>"))
(allow file-write* (subpath "<workspace>"))

; Temp dirs (read-write)
(allow file-read* file-write* (subpath "/var/folders"))
(allow file-read* file-write* (subpath "/private/var/folders"))
```

**Key decisions:**
- `mach-lookup` and `sysctl-read` left unrestricted (macOS 26/Tahoe needs services
  not in Anthropic's older list; these are not meaningful attack surfaces)
- `(allow file-read* (literal "/"))` required because `/bin`, `/tmp`, `/usr` are
  symlinks in the root directory — the dynamic linker needs to read root to resolve them
- `sandbox-exec` does NOT support `--` separator (discovered during testing)
- Use full path `/usr/bin/sandbox-exec` for invocation
- Shell environment is cleared (`env_clear`) and only essential vars passed through

**Test results:**
```bash
cato run
$ touch test.txt          # ✓ workspace
$ touch /tmp/ok.txt       # ✓ /tmp
$ touch ~/blocked.txt     # ✗ Operation not permitted
$ ls ~/Documents          # ✗ Operation not permitted
$ exit
```

### Step 2: deny_read — block reading sensitive files ✅

**Goal:** `deny_read` patterns blocked at kernel level.

**Build:**
- Parse `deny_read`, resolve glob patterns to Seatbelt regex
- Add `(deny file-read-data (regex ...))` rules AFTER workspace allow (later rules override)
- Add `(deny file-write-unlink ...)` to prevent move/rename bypass
- Protect `.cato.toml` from writes (tamper-proof)

**Implementation decisions:**
- Seatbelt uses "last rule wins" for conflicts at the same specificity
- Deny rules placed after all allow rules to ensure they take precedence
- Glob-to-regex conversion: `*.env` → `.*/[^/]*\.env`
- Double-star: `**/.ssh/*` → `.*/.ssh/[^/]*`
- Patterns without `/` get `".*/` prefix (match anywhere in path)

**Test results:**
```bash
cato run
$ echo "SECRET=x" > .env
$ cat .env                             # ✗ Operation not permitted
$ cat secret.key                       # ✗ Operation not permitted
$ python3 -c "open('.env').read()"     # ✗ PermissionError: Operation not permitted
$ cat main.rs                          # ✓ works
$ echo "hacked" >> .cato.toml          # ✗ Operation not permitted
```

### Step 3: Network restrictions ✅

**Goal:** Only allowed domains reachable.

**Build:**
- Seatbelt blocks ALL outbound except localhost (kernel-enforced)
- Local HTTP CONNECT proxy on localhost filters by domain
- Proxy env vars (`http_proxy`, `https_proxy`) injected into sandbox
- Proxy only tunnels to domains in the `network` allow list

**Implementation decisions:**

Seatbelt's `(remote ip ...)` filter only supports `*` or `localhost` as host — it
CANNOT filter by specific remote IP addresses. This is a fundamental Seatbelt limitation.

Solution: two-layer enforcement:
1. **Kernel layer (Seatbelt):** All outbound blocked except localhost — even if a process
   ignores proxy env vars, it cannot reach the internet directly
2. **Proxy layer (localhost):** HTTP CONNECT proxy validates domain against allow list.
   Allowed → tunnel established. Denied → 403 Forbidden.

Architecture matches Anthropic's `sandbox-runtime` which uses the same approach
(HTTP proxy + SOCKS5 proxy on localhost with Seatbelt blocking direct outbound).

**Key details:**
- If `network = []` (empty): all outbound allowed, no proxy started
- If `network = ["github.com", ...]`: proxy started, only listed domains reachable
- Wildcard support: `*.github.com` matches `api.github.com`, `raw.github.com`
- DNS is also blocked (proxy handles resolution on behalf of the sandboxed process)
- `no_proxy = localhost,127.0.0.1,::1` — local dev servers bypass proxy

**Bug fixed:** `deny_read` patterns like `*.pem` were catching system files
(`/etc/ssl/cert.pem`). Fixed by scoping deny patterns to workspace only using
Seatbelt's `require-all` combinator.

**Test results:**
```bash
# .cato.toml: network = ["example.com", "github.com"]
cato run
$ curl https://example.com     # ✓ 200 (allowed)
$ curl https://github.com      # ✓ 200 (allowed)
$ curl https://google.com      # ✗ 000 (blocked - proxy denies)
$ curl https://evil.com        # ✗ 000 (blocked - proxy denies)
```

### Step 4: Tool registration + selective binary access ✅

**Goal:** `cato tool add` registers binaries. Sandbox only allows those paths.

**Build:**
- `cato tool add/list/remove` commands
- `~/.cato/store.toml` management
- Seatbelt profile allows only registered tool paths
- `cato run` checks tools before entering

**Implementation decisions:**
- Tool paths stored in `~/.cato/store.toml` under `[tools]`
- When running `cato tool add` from a project directory, also adds to `.cato.toml` tools list
- Tool resolution: check store first, fall back to `which`
- Missing tools block sandbox entry with actionable error messages
- Note: Currently system paths (`/usr`, `/bin`, `/opt/homebrew`) are allowed read-only,
  so tools in those locations work without explicit registration. Registration is for
  tracking/validation and future stricter modes.

**Test:**
```bash
cato tool add node
cato run
$ node --version              # ✓ works
$ python3 --version           # ✓ (available via /opt/homebrew read access)
```

### Step 5: Secrets injection ✅

**Goal:** `cato secret put` stores values. `cato run` injects as env vars.

**Build:**
- `cato secret put/list/remove` commands
- Read from `~/.cato/store.toml` or host env
- Inject into sandbox as env vars
- `~/.cato/store.toml` not visible inside sandbox

**Implementation decisions:**
- Secret resolution order: host env var → project-scoped store → global store → default → warning
- Project-scoped overrides stored under `[secrets.projects."/path/to/project"]` in store.toml
- `cato secret put --project` stores to project scope
- Values masked in `cato secret list` output
- Secrets passed via `cmd.env()` in the sandbox runner (process environment)

**Test:**
```bash
cato secret put ANTHROPIC_API_KEY
# Enter value: sk-ant-...
cato run
$ echo $ANTHROPIC_API_KEY     # ✓ shows value
$ echo $CATO_SANDBOX          # ✓ shows "1"
$ cat ~/.cato/store.toml      # ✗ not visible (home dir invisible)
```

### Step 6: SSH agent forwarding ✅

**Goal:** Git push via SSH without exposing key files.

**Build:**
- Forward `SSH_AUTH_SOCK` when `ssh_agent = true`
- Allow socket path in Seatbelt profile
- Allow `system-socket (socket-domain AF_UNIX)` for the socket connection
- Allow `network-outbound` on the socket parent directory

**Implementation decisions:**
- SSH agent socket path is dynamic (from `SSH_AUTH_SOCK` env var)
- Allow read/write on the socket's parent directory
- Allow network-outbound to the unix socket path
- Key files (`id_rsa`, `id_ed25519`) still blocked by deny_read patterns

**Test:** (needs manual verification with git push)
```bash
cato run
$ ssh -T git@github.com      # should authenticate via agent
$ cat ~/.ssh/id_rsa           # ✗ blocked (deny_read pattern)
```

### Step 7: Ephemeral mode ✅

**Goal:** `cato run --ephemeral` — disposable workspace copy.

**Build:**
- Copy workspace to `/tmp/cato-eph-XXXXX/`
- Sandbox on the copy
- Delete on exit
- Skip `.git` directory during copy (speed)

**Implementation decisions:**
- Uses `std::process::id()` for unique temp dir name
- Recursive copy skips `.git` for speed
- Cleanup happens after sandbox exit

**Test:**
```bash
cato run --ephemeral
$ echo "modified" >> README.md
$ exit
$ cat README.md  # unchanged
```

### Step 8: Single command mode + audit ✅

**Goal:** `cato run -- <cmd>` and sandbox event logging.

**Build:**
- Arguments after `--` passed as command (clap `#[arg(last = true)]`)
- Forward exit code from sandboxed process
- Log sandbox_start/sandbox_stop to `~/.cato/audit.jsonl`

**Implementation decisions:**
- `sandbox-exec` does NOT use `--` separator itself — we just pass the command directly
- Exit code from `cmd.status()` is forwarded via `std::process::exit()`
- Audit log uses JSON lines format with timestamp, event type, workspace info
- `CATO_DEBUG=1` env var prints full Seatbelt profile and exit codes

**Test:**
```bash
cato run -- /bin/echo "hello"        # prints "hello"
cato run -- cat .env                 # exit code 1 (blocked)
cato run -- python3 -c "open('.env').read()"  # PermissionError
```

## Implementation notes (discovered during development)

### macOS Seatbelt gotchas

1. **Root directory symlinks**: On macOS, `/bin`, `/tmp`, `/usr`, `/etc` are all
   symlinks in the root directory (`/`). The dynamic linker must read the root
   directory to resolve them. Requires: `(allow file-read* (literal "/"))`.

2. **`sandbox-exec` does not support `--`**: Unlike most Unix tools, `sandbox-exec`
   does not use `--` to separate its flags from the command. Just pass the command
   directly after the profile argument.

3. **Mach services vary by macOS version**: Anthropic's hardcoded service list
   (from their sandbox-runtime npm package) works on their target macOS versions but
   fails on macOS 26 (Tahoe/Darwin 25.x). Use unrestricted `(allow mach-lookup)` —
   mach IPC is not a meaningful attack surface for file/network sandboxing.

4. **`sysctl-read` similarly version-dependent**: zsh 5.9 on macOS 26 reads sysctls
   not in any known whitelist. Use unrestricted `(allow sysctl-read)`.

5. **Profile escaping**: Seatbelt regex uses single backslash for escaping (e.g., `\.`
   for literal dot). When generating from Rust, use `"\\."` not `"\\\\."`.

6. **`file-read-metadata` vs `file-read-data`**: `file-read-metadata` allows stat()
   only. `file-read*` includes metadata + data + xattr. Path traversal needs metadata
   globally, but data reads should be restricted to specific paths.

7. **Deny rule ordering**: In Seatbelt, later rules override earlier ones when specificity
   is equal. Place deny rules AFTER allow rules to ensure they take effect.

8. **Environment clearing**: `env_clear()` is essential for security (prevents leaking
   host secrets). Only pass through: HOME, USER, SHELL, TERM, LANG, PATH, plus
   explicitly declared secrets.

### Differences from Anthropic's sandbox-runtime

| Aspect | Anthropic | Cato |
|--------|-----------|------|
| Model | Sandbox individual commands | Sandbox entire shell session |
| Base | `(allow default)` + denies | `(deny default)` + allows |
| Agent location | Agent runs outside sandbox | Agent runs inside sandbox |
| Auth | Agent has full host access | Secrets injected as env vars |
| Mach services | Specific whitelist | All allowed |
| Network | Proxy-based domain filtering | IP-based (planned) |
| Home directory | Partially visible | Invisible (only shell dotfiles) |
